# Запуск ИИ-менеджера: пошаговая инструкция

Шаги 1–2 делаются один раз для всего сервиса. Для каждого нового клиента — раздел «Новый клиент (пилот МСБ)».

## Новый клиент (пилот МСБ) — ~30 минут

1. Клиент регистрируется в панели своим email.
2. Админка (`/admin`) → подписка клиента: `max_dialogs_per_month` с запасом (10 заявок/день → **500**), `max_bots` = 1.
3. Клиент (или вы под его аккаунтом) создаёт бота → **Настройки → О компании и ИИ**:
   - тип бизнеса — «Обычный бизнес»;
   - название компании, имя ассистента (необязательно);
   - «Чем занимается компания» — 2–3 предложения: что продаёте, преимущества, доставка;
   - «Целевое действие» — когда клиент горячий: «выбрал товар и готов оформить заказ», «согласен на бесплатный замер» и т.п.;
   - модель — Haiku 5.5 (Sonnet дороже в ~19 раз, для МСБ невыгоден).
4. **База знаний → Общая**: прайс (лучше Excel: строка = товар/услуга + цена), доставка, оплата, гарантия, частые вопросы.
   Города не нужны, если бизнес в одном городе.
5. **🧪 Тест бота**: 10–15 сообщений как клиент — цены, возражения («дорого»), «беру». Проверьте, что бот не выдумывает
   и ставит 🔥 в нужный момент. Правьте анкету/базу знаний, пока не устроит. Ничего не уходит в WhatsApp.
6. **Уведомления**: chat_id менеджера клиента (он пишет /start боту уведомлений) → «Тест».
7. **WhatsApp**: подключить Wazzup клиента (шаг 3 ниже) и написать на номер с личного телефона.

Себестоимость для 10 заявок/день — см. `Юнит-экономика ИИ-менеджера.xlsx` (Haiku ≈ 2–7 тыс. ₸/мес вместе с хостингом).

## 1. База данных (Supabase)

1. Supabase Dashboard → **SQL Editor** → New query.
2. Вставьте целиком файл `backend/migrations/001_wazzup_cities_statuses.sql` → **Run**.
   Миграцию можно запускать повторно — она ничего не ломает и не удаляет.
3. В админ-панели сервиса (`/admin`) поднимите клиенту лимит диалогов
   (`max_dialogs_per_month`) — минимум **3500** для 1500–3000 заявок. Иначе бот замолчит после 100 диалогов.

## 2. Переменные окружения (Railway → Variables)

Обязательно добавить:

| Переменная | Что это |
|---|---|
| `ANTHROPIC_API_KEY` | ключ Claude API (console.anthropic.com) |
| `TELEGRAM_NOTIFY_BOT_TOKEN` | токен Telegram-бота для уведомлений сотрудникам (создать у @BotFather) |
| `BACKEND_URL` | публичный адрес сервиса, например `https://aisalesmanager-production.up.railway.app` |

По желанию:

| Переменная | Что это |
|---|---|
| `OPENAI_API_KEY` | расшифровка голосовых клиентов (~0,3 цента за минуту). Без ключа бот попросит написать текстом |
| `DEFAULT_AI_MODEL` | `claude-haiku-5-5` (по умолчанию) |
| `REPLY_DEBOUNCE_SECONDS` | пауза перед ответом, по умолчанию 6 с (клиент часто пишет 2–3 сообщения подряд) |
| `TELEGRAM_BOT_ID` | только если клиенты пишут ещё и в Telegram-бота: id бота из панели, которому идут эти сообщения. Без неё Telegram-канал для клиентов выключен |

Переменные `WAHA_API_URL` / `WAHA_API_KEY` больше не нужны — их можно удалить.

## 3. Wazzup

1. В личном кабинете Wazzup подключите номер WhatsApp (канал «WhatsApp», сканирование QR с телефона клиники).
   Тариф — **Max** (без лимита диалогов).
2. Wazzup → **Интеграции с CRM** → **API** → Добавить → скопируйте API-ключ.
3. В нашей панели: **Настройки → Wazzup** → вставьте ключ → «Проверить ключ» → выберите номер → «Подключить».
   Сервис сам пропишет вебхук в Wazzup. Статус канала должен стать «Активен».

> Один API-ключ Wazzup = один аккаунт = один адрес вебхука. Не подключайте этот же аккаунт Wazzup к другой CRM с вебхуками — она перезапишет адрес.

## 4. Города и база знаний (для сетей в нескольких городах)

> Для клиники: **О компании и ИИ → Тип бизнеса → «Медицинская клиника»** (иначе не будет правил про диагнозы и скорую 103). После миграции все существующие боты — «Обычный бизнес».

1. **Настройки → Города**: добавьте 7 филиалов. Для каждого:
   - название («Астана»), варианты написания через запятую («нур-султан, столица»);
   - адрес, телефон, график работы — коротко;
   - Telegram chat_id для уведомлений этого филиала (необязательно).
2. **Настройки → База знаний**:
   - «Общая» — то, что одинаково во всех городах (о клинике, правила записи, подготовка к анализам);
   - для каждого города — свой файл: услуги, цены, врачи, расписание.
   Лучше всего Excel/CSV: одна строка = одна услуга («Услуга | Цена | Врач | Длительность»).

Бот сначала спрашивает город, а затем видит **только** базу этого города + общую — чужие цены и адреса ему просто недоступны.

## 5. Уведомления в Telegram

1. Создайте бота у @BotFather → токен в `TELEGRAM_NOTIFY_BOT_TOKEN`.
2. Каждый сотрудник пишет этому боту /start (иначе Telegram не даст боту писать ему первым).
3. chat_id:
   - личный — написать @userinfobot, он пришлёт ваш id;
   - группа — добавить в группу бота уведомлений и @RawDataBot, id группы начинается с минуса (`-100...`), затем @RawDataBot можно удалить.
4. **Настройки → Уведомления**: общий чат руководителя, «через сколько минут напоминать о счёте» (по умолчанию 10), кнопка «Тест».

Что приходит:
- 🔥 **Горячий клиент — нужен счёт** — сразу, ответственным по городу;
- ⏰ напоминание, если за N минут никто не написал клиенту;
- 🚨 эскалация руководителю через 2N минут;
- ⚠️ **Нужен администратор** — вопрос вне базы знаний, срочные симптомы, клиент просит человека, прислал фото/документ.

## 6. Команда

Сотрудник регистрируется на странице входа своим email → владелец добавляет его в **Настройки → Команда** (email, город, Telegram chat_id).
Менеджер с городом видит только диалоги своего филиала, без настроек.

## 7. Проверка перед запуском рекламы

1. Напишите на номер клиники с личного телефона: «Здравствуйте, сколько стоит приём гинеколога?»
   → бот должен спросить город.
2. «Я из Караганды» → ответ по ценам Караганды.
3. «Хорошо, запишите меня на завтра» → в панели диалог стал 🔥, в Telegram пришло уведомление.
4. Ответьте клиенту с телефона клиники → в панели «ИИ на паузе — ответил сотрудник», бот замолчал.
5. В панели нажмите «Счёт отправлен» → «Оплачено» → проверьте статистику.

## Как это работает (коротко)

```
Клиент → WhatsApp → Wazzup → POST /webhook/wazzup/{bot_id}?token=…
  → сохраняем сообщение (защита от дублей)
  → ждём 6 с (вдруг клиент допишет)
  → город: по тексту + по ответу ИИ
  → база знаний только этого города → Claude Haiku 5.5
  → ответ клиенту через Wazzup API
  → горячий? → статус 🔥 + Telegram ответственным → напоминания
Сотрудник пишет с телефона/Wazzup/панели → бот в этом диалоге замолкает.
```

Ограничение: планировщик напоминаний и защита от параллельных ответов работают внутри одного процесса — держите в Railway **1 реплику** сервиса.

## Порядок выката (важно)

1. Сначала миграция в Supabase (шаг 1) и переменные в Railway (шаг 2).
2. Только потом push в GitHub — Railway задеплоит автоматически.
   Если задеплоить код раньше миграции, бот упадёт на отсутствующих колонках.
3. После деплоя: подключить Wazzup (шаг 3), города и базу знаний (шаг 4), прогнать проверку (шаг 7).
